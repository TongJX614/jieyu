话术小助手可拖到任意位置，双击它也能归位。
外部系统向 POST /api/ingest 投递顾客消息（字段 customerId、text，可选 msgId 用于幂等）。所有在线坐席通过 SSE 实时收到，断线重连会自动补拉，不丢消息。
示例：curl -X POST /api/ingest -H "Content-Type: application/json" -d '{"customerId":"allergy","text":"我用完脸红得厉害"}'
GET /api/orders/:customerId 取该客户全部订单；GET /api/order/:orderNo 凭订单号联查单笔订单详情，返回商品、SKU、实付金额、订单状态、物流、批次号、生产厂、关键成分、退换期与完整物流轨迹。
示例：curl http://localhost:5173/api/order/JD2026092611884
浏览器侧同一份数据由 assets/crm.js 提供（UMD，前后端共用），生产环境替换为真实 OMS / PIM / 履约接口即可。
AI 生成的每条话术都会做接地校验：话术里若没有出现订单号、商品名、批次号、订单状态或物流节点中任意一项，会被标记「未引用订单」；若三条全部未接地，系统会自动用本地订单事实生成一条顶到推荐位，保证坐席手里至少有一条基于订单的回复。
同时做出站合规检测：医疗功效承诺、孕产建议、超权限赔偿、诱导好评、对抗推责、私下交易命中即禁止发送；绝对化用语与效果承诺会给出「一键净化」。
每条顾客消息都跑同一条显式管线：facts → generate → vision → ground → compliance → emotion → context。话术生成走 agent → llm → local 降级链 —— Agent 会先调用工具核实订单 / 物流 / 知识库 / 处置标准，再组织话术（下方青色区块就是它的工具调用轨迹）；某一环失败自动落到下一环并在此处留下原因，每个阶段的耗时与判定都能核对，管线不是黑盒。
消息审计日志、风险事件与统计可一键导出为 JSON 文件。导出前按确定性规则脱敏（手机号 / 邮箱 / 证件号 / 订单号 / 客户姓名），审计需要的是「发生过什么」，不是「顾客是谁」；被总线拦截的消息不入册，图片只记 hasImage 布尔值，不导出图片本体。
直接双击打开 index.html 时浏览器会拦截跨域请求，系统会自动降级到本地引擎；要让真实模型生效，请在项目目录运行 npm start，改用 http://localhost:5173 访问。
服务端设置了环境变量 DEEPSEEK_API_KEY 时，浏览器侧无需再填写 Key；未设置时，代理会透传页面上填写的 Key。
