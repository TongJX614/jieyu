# 解语 Jieyu

> **美妆客服共情副驾** —— 听懂顾客没说出口的那半句

顾客在对话框里打下「我用完脸有点红」，一句话背后可能同时藏着三件事：她是谁、她买的是哪一支、她的怒气已经攒到第几句。

解语是一台**坐在客服坐席旁边的实时助手**。顾客每发一句话，它在同一秒把三样东西递到坐席手边：**她在意什么、这件事有多大风险、这句话该怎么回**。

它不替代客服，也不替客服说话。它把客服本来要翻四个系统、翻十页历史才能拼出来的判断，直接摆到屏幕上。

---

## 一、一个真实的下午

**14:31** 顾客发来一句：「我用完脸红得厉害。」

在大多数客服系统里，这一刻坐席要做的是：

- 打开订单系统，找她最近买的那支，确认批次和发货时间；
- 打开会员系统，看她是新客还是三年老客、是不是刚过期的大促订单；
- 翻聊天记录，确认她是第一次说，还是昨天就提过一次；
- 凭经验判断：这是「问一句」还是「要炸」；
- 然后一边打字安抚，一边提醒自己别承诺错。

**平均要花两到四分钟。而顾客的耐心通常只有十秒。**

在解语里，同一秒屏幕上就出现这些：

| 坐席看到的 | 具体内容 |
|---|---|
| 情绪 | 本句 28 分（愤怒）。从 66 一路掉下来，是**第三句**开始变差的 |
| 意图 | 过敏投诉，把握 94%。依据就是这句「脸红得厉害」 |
| 风险 | **高危** —— 同时命中「皮肤不良反应 + 疑似皮肤损伤 + 公开平台曝光倾向」，响应时限 15 秒 |
| 手上这件 | 她最近买的是紧致抗老精华 30ml，批次 AF-30，退换期还剩 6 天 |
| 能说的话 | 三条可以直接发出去的话术，每条都写明「依据订单 3 项」和引用了哪条 SOP |

坐席不必「先查清楚」再开口 —— 她可以边安抚边核对，因为在她说第一句话之前，该看的已经看完了。

## 二、它做三件事

### 1 · 读懂：把四路数据拧成一句人话

会员等级、订单、肤质档案、历史工单，本来是四个系统里的四张表。解语把它们合成一个人的完整样子：她是谁、买过什么、皮肤是什么底子、以前有没有闹过。

所以它认得出这些话背后的真意：

| 顾客说 | 表面看是 | 实际是 |
|---|---|---|
| 「我这个肤质会不会过敏？」 | 产品咨询 | 售前顾虑，需要的是**成分解释**，不是安慰 |
| 「还是不行」 | 一句废话 | 指代上一轮的过敏投诉，**情绪正在第二次下滑** |
| 「你们这个成分真的没问题吗」 | 质疑 | 成分安全 + 潜在舆情，回复里必须给批次检测报告 |
| 「算了不要了」 | 放弃 | 流失倾向，窗口只剩一两轮 |

它不只看最后一句。每条消息到达时，它会把前文一起冻结下来（最多 12 轮），所以「还是不行」这种没有关键词的句子，也能被判成过敏投诉的第二轮。

### 2 · 预警：不只报一个红点，还给处置动作

风险分级不是弹个红色感叹号就完事。解语会告诉你：**为什么高危**（命中了哪几个信号）、**现在该做什么**（升级资深客服 / 启动合规留档 / 暂停一切赔偿金额承诺）、**多久之内必须响应**（高危 15 秒，关注 2 分钟）。

它特别在意那些「听起来不严重、实际是红线」的话：

- 「孕妇能用吗」—— 只是一句普通咨询，分不高，但它是**医疗建议的合规边界**，必须按「关注」处理；
- 「我要发小红书」—— 单看只是一句气话，但它意味着**舆情外溢**；
- 「我朋友是律师」—— 涉法场景，不能当普通投诉处理。

这几类信号单独算分都不够高。所以系统给它们设了**底线**：一旦命中，等级不得低于「关注」，不允许因为「总分不够」被漏掉。

### 3 · 给答案：每条话术都能被核对

这是解语和「通用聊天机器人」最大的分别：**话术必须站在订单事实上，不能是聊出来的。**

每条建议都带三样东西：

- **依据订单 N 项** —— 引用了单号、商品、批次、物流里的哪几项，点开能看见；
- **接地生成** —— 没有引用任何订单事实的话术，不会出现在推荐位；
- **合规通过** —— 已经过了出站检查，能直接发。

如果模型这会儿不可用，它会用订单事实自己拼一份兜底话术，**不会让坐席空着手**。

## 三、它做到了别人没做的事

**① 话术必须接地，不允许「泛泛共情」。**
「非常理解您的心情」这类话在这里是废稿 —— 一条话术如果没有引用任何订单事实（单号 / 商品 / 批次 / 物流 / 退换期），会被标记为「未接地」，不进推荐位。因为顾客真正想听的是「您这单是 9 月 26 号买的，批次 AF-30，我帮您核过了」，不是「我理解您」。

**② 风险不止分级，还要管到结案。**
每条风险事件都会落成一张工单：有责任人、有流转状态、有首响时限。**时限只考核第一次响应** —— 接管、升级、结案的那一刻时钟就冻结，所以「15 秒内响应」是一个能被考核的数字，而不是永远显示同一句话。结案必须写处置结论，归档必须写复盘结论，重新打开必须写原因。

**③ 连「我们要说出去的话」也过一道闸。**
风险词屏蔽不只针对顾客，也针对坐席自己。诱导好评、引导私下交易、绝对化用语会直接**锁住发送**；医疗功效承诺、超权限赔偿会给**一键净化**的合规改写；对抗推责、贬损竞品会给**提示**但放行。

**④ 它把「AI 看了什么」摊开给你核对。**
话术小助手顶部有一条「前文体检」：已读前文几句、这是本轮第几句、是不是靠前文判的，点一下能回看 AI 读到的那几条原话。每条话术下面写着它引用了哪几项订单事实。**AI 的判断不再是黑箱** —— 坐席可以不同意它，但至少知道它依据什么。

**⑤ 一个人在不同渠道说的话，能拼到一起。**
她在天猫问成分、在小红书发空瓶记、回到天猫报不良反应 —— 三个渠道的痕迹按手机号和订单号归并成一个身份。只接一个渠道，你就只听得见一个渠道的人在说什么。

**⑥ 出事之前先开口。**
除了接住投诉，它还会主动提醒：这瓶安瓶按用量该用完了（复购窗口）、这位钻石卡会员今年的保级缺口还有多少、她购物车里的视黄醇和敏感肌档案冲突。**风险引擎管「出事之后怎么接住」，关怀雷达管「出事之前能不能先说话」。**

**⑦ 它不像一个后台系统。**
屏幕角落有一只会拿道具的小家伙：聊到口红它拿着口红，聊到眼影盘当场换过来，没人理它的时候会自己点点头、转个圈。这是刻意的 —— 客服每天要盯八小时屏幕，界面不该只有表格和红点。

## 四、五个可以现场演示的场景

每个场景都是完整的对话，点「自动演示」就会自己走一遍。

| 场景 | 顾客会说什么 | 你会看到什么 |
|---|---|---|
| **过敏投诉 · 舆情外溢** | 「用完脸红得厉害，我要发小红书」 | 高危预警、组合信号同时成立、15 秒倒计时、跨渠道看到她 6 小时前在小红书的留言 |
| **售前咨询 · 敏感肌抗老** | 「我这个肤质能用吗」「孕妇能用吗」 | 成分解释话术；孕产类问题被判为合规红线 —— 分不高，但等级被兜底抬高 |
| **彩妆选色 · 唇釉与眼影** | 「黄皮适合哪个色号」 | 品类识别、桌宠当场把道具换成口红 / 眼影盘、非标品推荐口径 |
| **物流纠纷 · 退款施压** | 「三天了还没到，直接退款吧」 | 履约时效信号、物流轨迹联查、零阻力退款话术 + 挽单窗口 |
| **会员挽回 · 权益流失** | 「算了不要了」 | 流失倾向、高净值识别、规则豁免与权益挽留话术 |

现场演示时，可以中途切到别的顾客再切回来 —— 每个会话独立缓存，**不会串台、不会丢**。

## 五、怎么跑起来

### 最快的方式：双击打开

直接双击 `index.html`。不装任何东西、不联网、不配置。此时没有服务端，也就没有账号可校验，页面会提供「以本机演示身份进入」——明确标成未登录，不假装是某个真实坐席。

全部界面、情绪曲线、风险预警、自动演示都能正常跑 —— 此时用的是内置规则引擎（不调用大模型）。适合现场网络不稳时兜底。

### 推荐的方式：本地服务 + 自己的 API Key

```bash
cd beauty-cs-copilot
npm start
```

打开 <http://localhost:5173>，会先看到**登录页**：用工号 `CS013`、口令 `1234` 进去（演示账号，页面右侧也列出了全部坐席，点一下就把工号填好）。

没登录看不到工作台 —— 会话里带过敏史、订单与投诉记录，登录是进入前的门，不是一层可以随手关掉的浮层。登录态存服务端，换一台设备用同一工号能接上；退出登录会重新回到登录页。

**没有工号？点「注册」现建一个**：工号 2–4 位字母 + 2–4 位数字（如 `CS102`），填姓名、岗位、口令（≥4 位）即可，建完直接进工作台，不用再登录一次。新工号从 L1 起，账号写进 `server/data/db.json`；同一工号不能重复注册。

进去之后，点右上角「未配置 Key」，填入 DeepSeek 的 API Key 即可。接口地址填 `https://api.deepseek.com`，系统会自动补全。

此时每条话术都由大模型生成，但仍然要经过订单接地校验与出站合规检查 —— **换成大模型不降低门槛，只会让话术更自然**。

演示账号：工号 `CS013`，口令 `1234`。

### Key 完全不出服务端的方式

不想在浏览器里填 Key，就交给服务端：

```bash
# macOS / Linux
export DEEPSEEK_API_KEY=sk-xxxxxxxx
npm start
```

```powershell
# Windows PowerShell
$env:DEEPSEEK_API_KEY = "sk-xxxxxxxx"
npm start
```

浏览器侧什么都不用填，代理会自己带上鉴权。Key 从头到尾没有进过浏览器。

### 换成别的模型

接口兼容任何 OpenAI 协议的服务（阿里云百炼、Moonshot、本地 Ollama）。在设置里改接口地址和模型名即可，其余不用动。

### 演示入口

这几个链接可以直接落到某一页，投屏时省掉点击：

| 链接 | 落在哪里 |
|---|---|
| `?s=1&play=1` | 打开即自动演示「过敏投诉」全流程 |
| `?view=dashboard` | 风险预警看板 |

## 六、项目里都有什么

只需要记住四个地方：

```
beauty-cs-copilot/
├── index.html          整个界面（导航 / 会话列 / 工作台 / 六个运营视图 / 浮层）
├── assets/             所有前端代码与素材，零构建、无打包器
│   ├── policy.js       ★ 风险与情绪的标准答案：等级、阈值、时限、处置动作，只此一处
│   ├── crm.js          演示用的会员 / 订单 / 批次 / 物流数据（换真实系统只改这一个文件）
│   ├── orderctx.js     ★ 订单事实层：把「她买了什么」装配成 AI 必须引用的事实
│   ├── guard.js        ★ 出站合规守卫：能发 / 要改 / 提醒三级
│   ├── casefile.js     风险工单：五态流转、责任人、首响时限、审计轨迹
│   ├── careradar.js    主动关怀雷达：复购、保级、成分冲突三路信号
│   ├── channels.js     八个渠道的接入要求、六步向导、token 生命周期
│   ├── jobqueue.js     ★ 分析任务队列：同一会话排队，不同会话互不等，全局最多两条在跑
│   ├── harness/        ★ 分析管线：八个阶段依次跑完，AI 的每一步都留痕
│   ├── app.js          界面与逻辑的接线处
│   └── img/            桌宠的序列帧与品牌标志
├── server/server.js    本地服务：静态托管 + 大模型代理 + 消息接入 + 账号与话术库
├── eval/               评测用的标注用例
└── tests/ tools/       自动化检查（开发用，演示不需要碰）
```

**想接真实系统改哪里**：`assets/crm.js` 换成真实 CRM / 订单中心调用，上层一行不用改；`assets/policy.js` 里的分值、时限、处置动作就是业务口径，改这一个文件，判级、看板、AI 提示词会同时生效。

## 七、几个常被问到的问题

**Q：它会不会替代客服？**
不会。它做的是「让客服在开口之前就知道该说什么」，发出去的话永远由人来定。所有建议都标着依据和把握，人可以不同意、可以改、可以不用。

**Q：AI 会不会瞎编？**
这是这套系统最较真的一点。话术必须引用订单事实（单号 / 商品 / 批次 / 物流），引用不到的不进推荐位；模型不可用时用订单事实拼兜底话术。所以它宁可少说，也不会编。
风险分数同理：模型自报的结论**不直接采用**，管线里有一道 `riskfloor` 对账闸，用词典口径复核（`取 max(模型自报, 词典累加)`，等级只许就高不许下调）。顾客说「烂脸了要投诉 12315」而模型只给 10 分时，界面显示的是词典算出的 80 分与「高危」，并且把「自报 10 / 词典 80 → 取 80」整条留在可展开的运行轨迹里。

**Q：顾客的照片会上传到云端吗？**
不会。皮肤照片在本机做像素统计，转成结构化观察（无泛红 / 轻度 / 中度 / 明显），原图不出浏览器。审计导出默认脱敏，手机号、证件号、订单号都会打码。

**Q：换一家品牌、换一套业务规则要改多少？**
判级口径只在一个文件里（`policy.js`），数据只在一个文件里（`crm.js`）。换品牌改配色令牌与文案，换业务改这两个文件。

**Q：演示时网络断了怎么办？**
会自动降级到内置规则引擎 —— 界面、曲线、预警、话术全照常，只是话术由规则生成而不是模型生成。**演示不会白屏。**

**Q：几个顾客同时来消息，会不会互相卡住？**
不会互等，也不会互抢。分析任务**按会话分桶**：同一个会话严格排队（情绪曲线和「谁答了谁」必须按到达顺序落回），不同会话并行，全局最多两条在跑 —— 这个上限是留给上游配额的，不是越多越好。时间预算同样**按轮**算：每轮分析盖一个自己的截止时刻，模型规划只许花本轮剩余的一部分；剩余不够一次往返时直接走本地引擎并在运行轨迹里写明「是预算不够」，而不是发一次注定被掐断的请求再报「模型失败」。
